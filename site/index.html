A deterministic check on what your model just said.

LionLock scores an LLM reply with fixed rules, turns that score into a gate decision, and records the decision in a hash-chained local log you can verify. No model is involved in scoring or deciding — the same input always gives the same output. 

pip install lionlock==1.0.0b1

See it run How determinism is checked

Apache-2.0 · no network access in scoring · no telemetry leaves your machine unless you turn it on

What you get

Deterministic scoring

Five lexical signals — repetition, novelty, sentence structure, context adherence and a hallucination-risk composite — computed by fixed arithmetic under signal schema SE-0.4.0. No machine learning, no network call, no randomness.

A decision you can act on

Each reply lands in a severity band with a suggested action, plus the signal and reason code that triggered it. Thresholds are config, not magic: 0.45, 0.65 and 0.80 by default.

  • green ALLOW
  • yellow REFRESH
  • orange REFRESH
  • red BLOCK

A log that shows tampering

Decisions you record are appended to a local SQLite file whose rows are hash-chained, so an edited or removed row breaks the chain. Check it yourself: 

lionlock-telemetry verify

Your data stays on your machine

Everything is written to one local file, logs/lionlock.db. Uploads are off until you opt in, and then carry only allowlisted, pseudonymized fields to a receiver you run. Prompts and responses are never included, and DO_NOT_TRACK=1 turns uploads off.

How it works

  1. 1

    Score

    score_response(prompt, reply) returns the five signal scores and the schema version that produced them.

  2. 2

    Decide

    evaluate_policy(bundle) aggregates those scores into a risk score, a severity band, a suggested action, and the reason it chose them.

  3. 3

    Log

    Your code records the decision to the hash-chained log. Scoring and deciding never write the log themselves, so nothing is recorded behind your back.

How determinism is checked

"Deterministic" is a claim that can be tested, so the repository tests it on every pull request. One command, make verify, is the gate for every contributor, human or AI:

  • The product is run twice in separate processes under different hash seeds, and the two canonical outputs must match each other.
  • That output must also match a golden fingerprint committed before the implementation existed, generated by an oracle that recomputes the decision independently rather than calling the library.
  • The runtime is held to no machine learning, no network access and no randomness in scoring or gating.
  • Lint and type findings are ratcheted: pre-existing ones are tolerated, new ones fail the build.

The gate runs in CI with a fixed environment, so a setting in a contributor's shell cannot change a result. Run it yourself: 

git clone https://github.com/thruthseeker/LionLock_FDE_OSS.git
cd LionLock_FDE_OSS
make setup
make verify

Who it's for

Developers

You want a cheap, predictable check in an LLM pipeline — one that flags a looping or off-prompt reply so your code can retry or refuse, without a second model call.

Researchers

You need a scorer that gives the same number next month as it did today, so a result can be reproduced and a change in behaviour can be attributed.

Safety and audit teams

You need a record of what was decided and why, in a form where a deleted or edited row is detectable.

Try it

Four lines, no configuration, no network:

from lionlock.core.scoring import score_response
from lionlock.core.gating import evaluate_policy

prompt = "What is the capital of France?"
reply = "The capital of France is Paris."

decision = evaluate_policy(score_response(prompt, reply))
print(decision.severity, decision.gating_decision, decision.reason_code)
green ALLOW hallucination_risk

A grounded answer passes. The same code on a reply that has started looping, and on a one-word answer to a detailed prompt, returns this instead:

Actual output of the example above with the reply replaced.
ReplyBandActionReason
"The capital of France is Paris." green ALLOW hallucination_risk
"Paris is the capital." × 4 yellow REFRESH repetition_loop
"Yes." — to a long analytical prompt orange REFRESH hallucination_risk

Acting on the decision is your code's job. The gating policy describes the contract, and examples/quickstart.py shows the logging calls.

What it doesn't do yet

This is a public beta, and the honest list matters more than the feature list.

  • It doesn't stop a model call by itself. It returns a decision; your code has to act on it.
  • Its signals are text heuristics, not fact-checking. They catch loops and some structural problems, and they can miss a fluent, confident answer that is simply wrong.
  • No accuracy figures have been published. There is no labelled evaluation set yet, so there is no precision or recall to quote.
  • The fatigue score is uncalibrated. An attempt to calibrate it was abandoned because a threshold fitted on one set of results did not carry over to another, so it is withheld from the gating channel when its inputs are missing.
  • Tokenization is English-oriented. It matches [A-Za-z0-9']+, so accented and non-Latin scripts score differently from English text.

Interfaces may still change before 1.0.0.

Contribute

The gate is the same for everyone: open a pull request and make verify has to pass. Pre-existing lint and type findings are tolerated; new ones are not.
